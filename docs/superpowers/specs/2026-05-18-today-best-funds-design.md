# 今日牛基（基金榜子 Tab）功能设计稿

日期：2026-05-18  
作者：AI（与牛宝确认后的设计结论）

## 1. 背景与目标

在「基金榜」页面新增一个与「全部 / 自选」同级的第三个视图入口，放在「分享」按钮之后，名称为**今日牛基**。

核心能力：

- 遍历全量基金，基于基金详情接口返回的**阶段同类排名**筛选出**TopN**。
- 支持筛选：
  - 周期（阶段：近1周/近1月/近3月/近6月/近1年/今年来/成立来等）
  - TopN（可自定义）
  - 基金类型（多选；类型来源必须来自基金详情接口）
  - 阶段涨幅（最小涨幅过滤，可选）
- 支持**刷新**：点击后清空结果并重新计算（不做日内缓存）。

非目标：

- 不引入“缺排名时用涨幅补齐”的兜底；缺 `rank/sc` 的基金**直接排除**。
- 不做跨天/日内缓存（每次进入或刷新都实时跑一遍）。

## 2. 用户交互与页面结构

### 2.1 顶部视图切换

基金榜标题行右侧按钮区现有：`全部` / `自选` / `分享`。

新增按钮：`今日牛基`（放在「分享」之后），与「全部/自选」同级，切换后影响列表数据源与筛选区展示。

前端状态新增：

- `selectedScope: 'all' | 'favorite' | 'today-best'`

### 2.2 今日牛基专用筛选区

切换到 `today-best` 时：

- 隐藏「按编码或名称搜索」（现有 `fund-discovery-filters` 的 keyword 输入）。
- 显示“今日牛基筛选区”（建议与现有表单控件风格一致：Tailwind + DaisyUI）。

筛选项：

1) **周期**（单选）
- 默认：近1周（`Z`）
- 选项：见 3.2 周期映射

2) **TopN**（数字输入 + 快捷按钮）
- 默认：1
- 约束：`1 <= topN <= 200`（上限可调，避免极端请求）
- 快捷：1/3/5/10/20/50

3) **基金类型**（多选）
- UI：checkbox 下拉（不限制即“全部类型”）
- 类型来源：基金详情接口（见 3.1）

4) **阶段涨幅筛选**（可选）
- `minReturn`（最小涨幅，单位 %；为空表示不启用）

5) 操作按钮
- **刷新**：点击后清空当前结果、进度归零，重新开始计算
-（可选）停止：取消正在进行的计算

### 2.3 结果表格

列建议：

- 序号
- 基金代码
- 基金名称
- 基金类型
- 阶段涨幅（按当前周期）
- 同类排名（`rank/sc`）
- 操作：详情（复用现有详情弹层）、加入自选

进度/状态提示（不 toast 轰炸）：

- 顶部显示一行：`已处理 A/B | 命中 X | 失败 Y`
- 完成后 toast 一条汇总：`计算完成：命中X，失败Y`

## 3. 数据口径与字段抽取

### 3.1 数据来源（必须符合约束）

所有用于计算“今日牛基”的字段均来自：

- `GET /api/funds/<fund_code>/overview`
  - 后端目前透传 `items[]`（KV 结构，含 `section/key/value`）
  - DefaultDataSource 走东方财富 j5 详情接口解析（`warehouse/adapters/eastmoney_j5_fundinfo.py`）

其中：

- **同类排名 / 同类总数 / 阶段涨幅**：来自 `section === 'JDZF'` 的 items，key 形如 `Z.rank`、`Z.sc`、`Z.syl`
- **基金类型**：来自 `section === 'JJXQ'` 的 items（以实际 key 为准，通常是 `FUNDTYPE` 或等价字段）

### 3.2 周期映射（UI 文案 ↔ JDZF code）

沿用项目现有 JDZF 周期码：

- 近1周：`Z`
- 近1月：`Y`
- 近3月：`3Y`
- 近6月：`6Y`
- 近1年：`1N`
- 近2年：`2N`
- 近3年：`3N`
- 近5年：`5N`
- 今年来：`JN`
- 成立来：`LN`

默认：`Z`

### 3.3 排除规则（你已确认）

当且仅当以下条件全部满足时，基金可参与排序：

- `rank` 存在且可解析为整数
- `sc` 存在且可解析为整数

缺 `rank/sc`：直接排除（不补齐）。

阶段涨幅 `syl`：

- 若 `minReturn` 未启用：允许 `syl` 解析失败（按 `null` 展示）
- 若 `minReturn` 启用：`syl` 必须可解析为数值，否则排除

### 3.4 排序与截断

排序规则（稳定）：

1. `rank` 升序（1 最好）
2. `syl` 降序（rank 相同时涨幅高优先；`null` 视为最小）
3. `fund_code` 升序（保证结果稳定）

最后取前 `topN`。

## 4. 性能与接口设计（推荐实现）

### 4.1 性能问题说明

“遍历所有基金 + 每只基金调 overview”在纯前端逐个请求时会产生海量 HTTP 调用，容易：

- 浏览器并发限制导致极慢
- Flask 单进程/线程压力过大
- 触发外部数据源限流

因此推荐新增轻量批处理接口，仍然调用同一条“基金详情解析链路”，只做**合并与并发控制**。

### 4.2 新增 API（推荐）

1) 全量基金代码列表（用于遍历候选集）

- `GET /api/funds/all-codes`
- 返回：
  - `success: true`
  - `items: [{ fund_code, fund_name }]`
- 数据来源：复用仓库层基金列表缓存（避免重新抓取与分页循环）

2) 基金详情批量获取（overview-batch）

- `POST /api/funds/overview-batch`
- 入参：`{ fund_codes: string[] }`
- 返回：
  - `success: true`
  - `items_by_code: { [fund_code]: items[] }`
  - `errors: { [fund_code]: message }`
- 行为约束：
  - 内部调用 `fund_repository.get_fund_overview(code)`（与单只 overview 完全一致）
  - 控制并发（线程池），建议默认 8~16
  - 单基金超时/异常记录到 `errors`，不中断整体

> 说明：这并不改变“基金类型必须来自详情接口”的口径，只是把 N 次调用收敛到批处理，提升吞吐并保护服务端。

## 5. 前端执行流程（进入与刷新同逻辑）

触发时机：

- 切换到「今日牛基」视图：自动执行一次（默认：近1周 Top1）
- 点击刷新：**清空结果**并重新执行

流程：

1. 清空 UI：结果表、命中数、失败数、进度归零
2. 请求 `/api/funds/all-codes` 获取候选基金 codes
3. 分批调用 `/api/funds/overview-batch`（每批 50~100）
4. 每批返回后：
   - 解析每只基金的 `items[]`，抽取 JJXQ 类型与 JDZF 周期数据
   - 应用筛选（类型多选、minReturn）
   - 将候选加入临时数组
   - 更新进度 UI（已处理/失败/命中）
5. 全部批次完成：
   - 按 3.4 规则排序 + 截断 TopN
   - 渲染最终结果
   - toast 汇总

取消机制：

- 切走视图或点击“停止”时：
  - 取消后续批次请求（前端使用 `AbortController` 或任务 token）
  - 停止后保持当前空表/或保持部分结果（本期设计建议：停止即保持当前已计算但不再继续；刷新会清空再来）

## 6. 错误处理与提示规范

- 单基金失败：不弹 toast（防止几千条失败刷屏），仅计数
- 批接口失败：提示一次“批次请求失败”，允许继续下一批/或直接中止（实现可选；默认建议中止并提示）
- 完成汇总 toast：`计算完成：命中X，失败Y`

## 8. 关键假设与默认值

- 默认周期：近1周（`Z`）
- TopN 默认：1；上限默认 200
- overview 的 JDZF key 结构保持为 `<周期>.(syl|rank|sc)`（与现有 `buildJdzfModel()` 一致）
- 基金类型字段以 JJXQ 实际返回为准；若存在 code+name 则使用二者，否则仅用 name 作为筛选值
